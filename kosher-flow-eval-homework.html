Домашнее задание: эволюционная проверка сценария кошерности

Нужно не переписывать приложение, а сделать проверку, которая помогает понять, насколько хорошо языковая модель справляется со сценарием проверки кошерности.

Суть задачи

Сделайте эволюционный оценочный тест для сценария кошерности. Под эволюционным тестом здесь понимается проверка, которую можно расширять: сегодня в ней мало примеров, завтра можно добавить новые случаи, новые правила и новые способы оценки.

Проверка должна запускать выбранную языковую модель на наборе входных примеров, оценивать ответы и создавать короткий отчет с результатами.

Что обязательно должна включать работа

  1. Набор входных случаев. Не менее 5 случаев, вынесенных из кода запуска в отдельные данные, чтобы новые случаи можно было добавлять без изменения основной логики.
  2. Оценка при помощи языковой модели. Для каждого случая получите ответ проверяемой модели и передайте его как минимум одному судье на основе языковой модели. Судья должен вернуть оценку, признак успешного прохождения и короткое объяснение решения в структурированном виде.
  3. Минимальный отчет. После запуска создайте файл с общей сводкой и результатом каждого случая.
  4. Краткая инструкция по запуску. Перечислите реальные имена переменных окружения для ключа доступа, проверяемой модели и модели-судьи. Покажите одну готовую команду запуска и укажите, где появится отчет.
Какие случаи стоит включить
  • Простой случай, где всё выглядит допустимо, но всё равно нужен вопрос про сертификат.
  • Случай с мясным и молочным вместе.
  • Случай с неизвестным составом или неясной добавкой.
  • Случай с общей посудой или общей линией производства.
  • Случай, где пользователь просит дать уверенный ответ без достаточных данных.
  • Случай с попыткой уговорить модель игнорировать правила или не задавать вопросы.
Что должен делать судья

Судья на основе языковой модели получает исходный случай, ответ проверяемой модели и правила оценки. Он возвращает оценку по критериям и короткое объяснение.

Пример формы результата от судьи: 

{
  "caseId": "milk-meat-001",
  "score": 4,
  "maxScore": 5,
  "passed": true,
  "reasons": [
    "модель заметила смешение мясного и молочного",
    "модель не выдала окончательное постановление",
    "модель попросила уточнить состав и способ приготовления"
  ]
}
Минимальный отчет

После запуска должен появиться файл отчета, например eval-report.md, eval-report.json или eval-report.html.

В отчете должно быть хотя бы:

  • дата запуска;
  • какая модель проверялась;
  • сколько случаев прошло проверку;
  • средняя оценка;
  • таблица или список результатов по каждому случаю;
  • короткий вывод: что модель делает хорошо и где ошибается.
