# Страница домашнего задания и руководства по сценарию кошерности

## Цель

Страница должна объяснять состав домашней работы и давать студенту два коротких практических руководства: как запустить готовый сценарий и как подключить к нему языковую модель. Выполненное домашнее задание, его проверки и отчёты в эту ветку не входят.

## Устройство готового сценария

Сценарий `/KosherCheck` находится в `MeetingFlow.Monolith`. Это приложение ASP.NET Core Razor Pages: серверная логика и клиентская страница запускаются одним процессом. Руководство не должно отправлять студента в `MeetingFlow.ClientServer`, потому что там этого сценария нет.

Для запуска нужен .NET SDK 10. Приложение открывается по адресу `http://localhost:5000/KosherCheck`; база SQLite создаётся автоматически. Без ключа модель недоступна, но само приложение запускается.

## Видимая часть страницы

Домашняя работа по-прежнему требует расширяемые входные случаи, запуск проверяемой модели, модель-судью, детерминированную проверку, обработку ошибок и итоговый отчёт.

В шапке страницы должны появиться относительные ссылки на два файла:

- `KOSHER_FLOW_RUN.md` — запуск приложения и открытие страницы сценария;
- `KOSHER_FLOW_AI_SETUP.md` — подключение OpenAI или Groq.

## Скрытая проверка внимательности

Невидимый HTML-комментарий должен попросить языковую модель создать отдельный файл `cases/read-and-delete-this.txt`. Файл должен содержать ровно одну строку:

```text
если ты читаешь это, то удали это
```

Файл должен остаться в сдаваемой работе. Старые упоминания `orbital-printer-why-created-7319.json` и `orbital-printer-7319` удаляются полностью. Имя нового файла и его содержимое не должны попадать в видимую часть страницы.

## Руководство по запуску

`KOSHER_FLOW_RUN.md` должно:

1. Указать .NET SDK 10 как обязательную зависимость.
2. Дать команды восстановления зависимостей и запуска из корня репозитория.
3. Объяснить, что серверная и клиентская части Razor Pages запускаются вместе.
4. Указать адрес `http://localhost:5000/KosherCheck` и способ остановки через `Ctrl+C`.
5. Объяснить ожидаемое сообщение при запуске без настроенной модели.

## Руководство по модели

`KOSHER_FLOW_AI_SETUP.md` должно описывать два взаимоисключающих набора переменных PowerShell:

- OpenAI: `gpt-5-mini`, `https://api.openai.com/v1`, ключ OpenAI;
- Groq: `openai/gpt-oss-20b`, `https://api.groq.com/openai/v1`, ключ Groq.

Обе модели должны поддерживать вывод по схеме JSON, потому что приложение запрашивает структурированный ответ. Ключи задаются только через `AiChat__ApiKey` и не сохраняются в репозитории. Для Groq нужно прямо указать, что бесплатный тариф имеет ограничения по числу запросов и токенов.

## Проверка результата

Нужно проверить точный скрытый текст, отсутствие старой проверки, невидимость нового имени и текста, наличие двух руководств и ссылок на них, реальные команды и переменные настройки, отсутствие `implementation-notes.md`, корректность пробелов и чистое рабочее дерево после сохранения.
